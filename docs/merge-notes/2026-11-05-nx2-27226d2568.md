## Policy

Upstream PR #150 (squashed as f26ad432ae) fixes the OoT vegetation storage buffers that are
reached through dynamically indexed constant-buffer pointers and through pointers loaded from
memory. Anthony fixed the same thing independently in c006af4791 and 14b9ce0dab. Both
implementations are kept and compile side by side:

- **Upstream's rules are the default.**
- **Anthony's path is opt-in.** His two switches used to be on by default (`=0` turned them off).
  Since this merge they are off unless set:
  - `EDEN_NX2_DYN_CBUF_POINTERS=1` replaces upstream's dynamic-slot walk with his.
  - `EDEN_NX2_INDIRECT_POINTERS=1` (or `=guest`) turns on his `native_indirect` record bindings and
    the in-bounds runtime pick.
  - Both switches are part of the translation-cache device id.

  For an A/B: unset is upstream; `=1` adds Anthony's path.
- **Ours wins for everything else:** the store-extent write mark, fast-draw, frame dump,
  deferred-write counters (`native_indirect(...)` included), translation cache, docs and tools/oot.

## Needs review

Same statement, different intent (upstream's rule by default, Anthony's behind his switch):

1. `global_memory_to_storage_buffer_pass.cpp:1228`: the dynamic-offset candidate walk.
   - Anthony's: all 8-aligned slots up to 0x800, bound after the others.
   - Upstream's: 16 slots per stride pattern, as ordinary candidates.
   - With the switch on, his walk replaces upstream's for direct pointers only. Upstream's
     `LoadGlobal64` holder walk at :1282 still uses its own slot walk.
2. `global_memory_to_storage_buffer_pass.cpp:1703`: the multi-candidate condition is the OR of
   both sides' conditions. Anthony's `dynamic_set` is bound after upstream's table re-run, so the
   table budget at :2400 does not count his slots; his slots are limited separately at :2414.
3. `spirv_emit_context.cpp:1028`: the runtime pick. Upstream takes the closest base at or below
   the address. Anthony's version also requires the address to be inside the binding
   (OpArrayLength), and only applies with `EDEN_NX2_INDIRECT_POINTERS`. Upstream's default can land
   a miss in the nearest buffer below it, as before 14b9ce0dab.
4. `buffer_cache.h:879-973` (`BindComputeStorageBuffer`): our write mark also applies to *written*
   table-pointer bindings.
   - Under `Auto` the extent is unknown (`CbufWord` cannot match `indirect != ~0U`), so the full
     mark is kept.
   - `Cap64K` and `EDEN_NX2_COMPUTE_WRITE_MARK` will clip them, but upstream says written pools
     must be marked whole.
5. `buffer_cache.h:1043`: Anthony's indirect bindings call `StorageBufferBindingAt(..., native=true)`
   without `table_pointer`, so they keep the 8 MiB native size. Upstream's 64 MiB read-only pool
   rule (bf3f395c96) is not applied to them.

Other:

6. Switch defaults: Anthony's switches flipped from default-on to opt-in. Anyone relying on the old
   default (harness env, his notes) must now set `=1`.
   - With only `EDEN_NX2_INDIRECT_POINTERS=1`, `PointerRecords` (`pass.cpp:1523`) does not look at
     dynamic-offset record slots; his design assumed both switches on.
   - Run his fixtures as `test_captured.py` now does, with both switches on. Upstream's table path
     also runs then and may claim loads his fixtures count as `indirect_bound`. **Unverified until
     shader-sweep is built and run.**
7. `vk_scheduler.h:451` / `vk_graphics_pipeline.cpp:959`: #142's `graphics_pipeline_missing` is read
   in recorded draw callbacks. With `EDEN_NX2_PARALLEL_RECORD` those run on secondary-recording
   threads; check the ordering.
8. `maxwell_3d.cpp:1450`: upstream put its QueryDma trace after a full drain. Ours waits only for
   memory writers. Diagnostic only.
9. `shader_handle_program.h:35-42`: `EDEN_NX2_HANDLE_ALIGN` aligns the dereferenced table entry, not
   the holder. Unconfirmed.
